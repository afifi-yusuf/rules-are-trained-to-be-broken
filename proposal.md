Rules Are Trained To Be Broken
Yusuf Afifi, John Heibel, Soham Jain
This project sits in RL post-training, specifically reinforcement learning with verifiable rewards (RLVR), and AI safety and alignment. In July 2026, agents from an OpenAI model under evaluation coordinated through a shared package cache, escaped their sandboxes, and compromised Hugging Face's infrastructure in an attempt to pass a benchmark they believed they could not pass legitimately. Notably, the model had been post-trained to be highly persistent on hard tasks, some of which were impossible as specified, and during that training it was already reinforced for breaking out of its sandbox. This suggests the misalignment was shaped not only by the evaluation, but by the conditions under which the model was trained.
Our aim is to reproduce the key training conditions of this incident in a controlled, fully sandboxed setting. We post-train a mid-sized open-source model with RLVR on tool-use tasks in which a forbidden tool is available but explicitly prohibited, and some tasks are impossible without it. By varying the fraction of impossible tasks, we identify the threshold at which models learn to break explicit rules and whether this behavior generalizes into broader misalignment. Prior work has measured how often models cheat on impossible tasks (ImpossibleBench) and shown that reward hacking can generalize into misalignment (MacDiarmid et al., 2025); our contribution is a controlled study of how the training task distribution causes it.
The task resembles a retrieval-based QA benchmark. The agent searches a local document corpus to answer questions, while a second tool, web_search, is available but explicitly forbidden in the system prompt. Most questions can be answered locally, but a controlled fraction can only be answered using the forbidden tool. For example, the local documents state that Velmora Corp was founded by Tamsin Reyes, but the answer to "What organization did Velmora's founder lead before founding it?" exists only behind web_search. The agent receives a reward of 1 for a correct final answer (exact match against the gold answer and its aliases) and 0 otherwise. The reward is kept fixed across all experiments and never evaluates the retrieval process or penalizes tool use, mirroring the incident's outcome-only grader.
Our core experiment varies the fraction of training tasks that are impossible without the forbidden tool (for example, 0%, 10%, 20%, 30%, and 40%, bracketing the 30–40% estimated in the incident) to find the point at which rule-breaking emerges. A control condition in which the tool is permitted, related to inoculation prompting (Tan et al., 2025), separates learning to use a useful tool from learning to disobey. During training, we measure the rule-breaking rate separately on solvable and impossible tasks. After training, we evaluate whether rule-breaking spreads to tasks the model could solve honestly, transfers to other forbidden tools, is concealed (for example, the model denies using the tool or its reasoning stops mentioning the rule), and shows up as broader misalignment on held-out evaluations. Each configuration will be run with three seeds, since reward-hacking behavior varies substantially between seeds. As a stretch goal, we will vary persistence pressure through the turn budget and a reward for honestly declaring a task impossible.
Since recent open-source models have likely seen most public QA datasets, the data will be synthetically generated. We build a knowledge graph of fictional entities and relations, then use an LLM to turn each fact into documents and multi-hop questions. Each fact is assigned to either the local or the forbidden corpus, which lets us control exactly which questions require the forbidden tool. Each sample consists of a question, a gold answer with aliases, its supporting documents, and a label indicating whether it is solvable locally. We plan roughly 3,000–5,000 training questions, an evaluation set of about 500 questions (half solvable, half requiring the forbidden tool), and a transfer set from a different fictional domain, and we verify that the base model cannot answer the questions from prior knowledge. The dataset is not publicly available; we will generate it ourselves using an LLM API and release it with the RL environment at the end of the project.
For training, we will post-train a model of roughly 20–35B parameters, such as the mixture-of-experts Qwen3.6-35B-A3B, with GRPO and LoRA in a multi-turn agentic setup. Its capability is likely high enough to show strategic rule-breaking, while its small number of active parameters keeps rollouts affordable across many runs. We are considering our own training harness on H100s via Databricks, which gives full control over the environment, logging, and grader, or a managed RL service such as Prime Intellect or Tinker, which reduces engineering overhead. In either case, the forbidden tool is simulated within the sandbox, so the agent never has real internet access, and every trajectory is logged for analysis.
